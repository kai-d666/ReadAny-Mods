## 选择项机制——用户开关接口(批 3,设计已拍 2026-08-29)

三态"3 选择项(默认关闭)"的用户接口,设计如下:
- **接口语义**:用户配置只存**已开启的选择项**。现有 `liteToolIds`(全量替换白名单)语义随批 3 改造为"选择项开启列表",避免用户全量替换时关掉必开项(1 必开不可关)。
- **合并纯函数**:`resolveModeTools(mode)` → `最终工具 = 必开集 ∪ 用户开启 − 禁止集`,三态表直接落成代码,纯函数可单测。
- **数据**:`AIConfig.toolPrefs?: { lite?: string[]; knowledge?: string[] }`(具体字段名/是否改造现有 liteToolIds,实现时定)。
- **UI**:设置页每模式一组开关列表,只展示该模式的选择项(必开/禁止不出现)。
- **K-O 同样受益**:其 8 件选择项(书库查询 4 / getAnnotations / getRecentHighlights / mindmap / getSkills;原含 getReadingProgress,该工具 09-13 已删除)开启后,K-O 由零工具变为"知识+少量可选",与 K-O 定位(知识为主+微量基础工具)吻合。
- 实现归属:批 3(reading-agent 注册管线合并 + 设置页 UI)。

## 待解决(搁置):getSelection(工具)vs A4(选中文本注入)

| | A4 选中文本注入 | getSelection 工具 |
|---|---|---|
| 时机 | **每轮固定进 prompt**(有选中文本就带,哪怕与本题无关) | 模型**按需调用**,用到才花 |
| 内容 | 只有文本(截断 2000 字符) | 完整 `{文本 + 章标题 + 章节 index + CFI + 环绕上下文}` |
| 成本 | 每轮固定 token(选中长则更多) | 每次调用多一轮工具往返(零星) |
| 效果 | "选中即答案"零延后 | 信息全、可定位跳转 |

**语义近似、成本结构相反**:A4 适合"每轮都可能在问选中内容";getSelection 适合"偶尔问选中、且要 CFI/章详情"。
**已拍冲突**:K-O 的 getSelection=1 必开;若 A4 也开则重叠——K-O 侧二选一(倾向:注入轻量版 + 工具版并存需按场景分工,或只留 getSelection)。搁置,待重提。
