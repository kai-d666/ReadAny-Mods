# 安卓构建:固化清单与坑(Windows)

> **状态**:active(现行 — 当前构建命令/补丁/验证标记,随代码维护)

> 2026-08-22 整理。RN 0.81 源码构建在 Windows 上官方不支持,所有补丁/就绪状态均已固化,
> 本文件是唯一权威说明。**不升级依赖就不会出问题;升级按"升级适配流程"操作。**

## 一、现状一句话

`app/build.gradle` 用 `implementation("com.facebook.react:react-android")`(AAR 坐标),
`settings.gradle` 用 `includeBuild('../../../node_modules/react-native')` 复合构建 +
显式 substitution 让 ReactAndroid **从源码参与构建**。所有原生改动通过 pnpm `patchedDependencies`
自动重放,构建所需就绪状态由 gradle 任务自动准备。

## 二、固化清单(patches/ 目录 + 自动任务)

| 项 | 位置 | 内容 |

## 三、环境配置(一次性,已配好)

1. **pnpm 安装方式**:`pnpm config set package-import-method copy`
   - 原因:Windows Defender 实时扫描拦截 pnpm 原子替换(`_tmp_` 目录被锁),增量 install 报 `ERR_PNPM_ENOENT scandir ..._tmp_...`
   - 症状:全量 install 成功、增量 install 失败
   - **换电脑/重装后必须重设**(用户级配置)
2. **磁盘 junction**(D 盘紧张):`app/build`、`ReactAndroid/build`、`hermes-engine/build` 三个目录
   junction 到 `G:\lingshiiiiiii\`(app-build / reactandroid-build / hermes-engine-build)
   - 构建产物全写 G 盘,D 盘只放源码
3. **构建前备份 workspace**:`mv pnpm-workspace.yaml pnpm-workspace.yaml.bak`(monorepo 提升规避),
   构建后恢复。注意:**git add -A 时 .bak 会被误提交**(先恢复再提交)

## 四、踩过的坑(全部)

### 原生改动不生效
- **症状**:改 node_modules 原生代码,构建 23s~2min,行为不变
- **根因**:react-android 是 Maven 预编译 AAR,源码不参与构建
- **解决**:includeBuild 复合构建(见下)

### includeBuild 的坑
- **不能 `include ':ReactAndroid'`**:单独 include 时 ReactAndroid 找不到 version catalog,
  报 `No variants exist`(catalog 在 react-native 包根 gradle/libs.versions.toml,只有复合构建根才生效)
- **路径级数**:`includeBuild('../../../node_modules/react-native')`(android → app-expo → packages → readany-src)
- **必须显式 substitution**:项目名 `ReactAndroid` ≠ artifactId `react-android`,自动替换不生效
- **hermes-engine 子项目**:react-native 自带 settings.gradle.kts 会 include hermes-engine;
  **必须给 react-native/settings.gradle.kts 加 `includeBuild("../@react-native/gradle-plugin")`**(否则 classpath 解析失败)

### Hermes(无 MSVC 环境)
- **hermesc 不能源码编译**(需要 MSVC/NMake):用 npm 包自带预编译 `sdks/hermesc/win64-bin/hermesc.exe`
- hermes-engine/build.gradle.kts 需 patch:configureBuildForHermes/buildHermesC 空转(`cmd /c exit 0`)
- CMake 参数必须加 `-DHERMES_ENABLE_TOOLS=False`、`-DHERMES_ENABLE_TEST_SUITE=False`(host 工具/测试在 Android 交叉编译下必然失败)
- `ImportHermesc.cmake` 路径**必须正斜杠**(反斜杠 = CMake 转义符,报 `Invalid character escape`)
- Hermes 源码(sdks/hermes)install 后丢失 → 已固化(自动解压)

### ReactAndroid 第三方依赖下载
- downloadDoubleConversion/Fmt/Glog/Folly 等任务**并发时网络抖动失败、单独跑成功**(缓存命中)
- 依赖 tar 缓存于 `G:\lingshiiiiiii\reactandroid-build\downloads\`(junction 保留)

### static-server pcre2
- pcre2-config 是 POSIX sh 脚本,Windows 不可执行 → patch 指向模块 sysroot 的预构建 pcre2
- 包升级后 patch 上下文失效(应用失败) → 重新生成(见升级流程)

### 日志/调试
- **logcat 读不到 app 日志**:vivo 过滤 D 级以下 → **用 `Log.e`(E 级必定显示)**;adb server 重启后可能恢复
- **adb reverse 丢失**:adb kill-server/start-server 后 reverse 全丢,dev launcher 报
  `ConnectException: localhost:8081` → 重新 `adb reverse tcp:8081 tcp:8081`
- **设备名变化**:无线调试(mDNS)重连后设备名可能是 `adb-XXXX._adb-tls-connect._tcp`(或带 (2))

### 其他
- **patch 文件必须 LF**:CRLF 的 patch git apply/pnpm 报 corrupt
- **node_modules 被占用**:Metro/gradle 运行中 `rm -rf node_modules/react-native` 报
  `Device or resource busy` → 先停 Metro/gradle
- **pnpm install 中途失败**:残留 `package_tmp_XXX` 目录 → 删掉重试;反复失败 → 删整个 node_modules 全量装

## 五、升级适配流程(RN 或依赖升级时)

1. `pnpm install`(新版本)→ patch 应用失败(预期)
2. **重新生成 react-native patch**:
   - 下载新版本官方包:`curl -o rn-X.Y.Z.tgz https://registry.npmmirror.com/react-native/-/react-native-X.Y.Z.tgz`
   - 解压 → `git init && git add -A && git commit`(基线)
   - 把改动文件(ReactEditText.kt/settings.gradle.kts/hermes-engine/build.gradle.kts/cmake-utils 的 LTO)拷入
   - `git diff > patches/react-native-readany.patch`(注意 LF,`git -c core.autocrlf=false`)
3. **Hermes 版本同步**:`.hermesversion` 变了 → 重新下载 hermes tar 替换 `patches/react-native/hermes-src/hermes.tar.gz`
4. **static-server 等**:同法重新生成(0.26.2 基线)
5. `pnpm install` 验证 patch 应用(检查关键标记:suppressBlurScroll / CMAKE_HOST_WIN32 / HERMES_ENABLE_TOOLS)

## 六、常用命令

```bash
# 构建(release/debug,arm64-only)——2026-08-27 起 release 走 mavenLocal 单源方案
cd packages/app-expo/android
mv ../../pnpm-workspace.yaml ../../pnpm-workspace.yaml.bak   # 构建前
./gradlew assembleDebug -PreactNativeArchitectures=arm64-v8a # 或 assembleRelease
# release(root repos 置顶 mavenLocal(),源码 ReactAndroid AAR 已发布 ~/.m2;
#   settings.gradle 不可加 includeBuild+substitution,双来源必撞 Dex;
#   默认 minify=true 可出包;D8(关 minify)亦可。详见 claude-index/ReadAny-安卓release构建-卡点交接.md)
mv ../../pnpm-workspace.yaml.bak ../../pnpm-workspace.yaml   # 构建后

# Metro(debug 热更新)
cd packages/app-expo && npx expo start --port 8081

# 设备连接
adb devices                                            # mDNS 自动发现
adb reverse tcp:8081 tcp:8081                          # adb 重启后必做
```
